# pvarki-adopt

Sets up a repository so every coding agent (Claude Code, Codex, Copilot,
Cursor, Gemini, Junie and others) follows the same rules. The templates are in
this skill's `templates/` folder: copy them, never retype the rules block
(`≤` and quotes drift).

## Steps

1. Branch.
   - `git fetch origin && git remote set-head origin --auto`
   - Find the default branch: `git symbolic-ref --short refs/remotes/origin/HEAD`
     prints `origin/<default>`.
   - Run `git switch -c agent-harness --no-track origin/<default>`. If you are
     updating and `agent-harness` already exists, switch to it instead.
2. Fix what is already there first. If the repo has `AGENTS.md`, `CLAUDE.md`,
   `.github/copilot-instructions.md` or `.cursor/rules/`, check every line
   against code and config:
   - Keep a line only if code or config confirms it.
   - Correct or drop the rest.
   - Claims about other repos need an evidence link, or they go.
   - Commit this as its own change (`docs: correct AGENTS.md against code`).
   - Write the list of dropped and corrected lines, with file:line evidence,
     into your report and the PR description. Never delete another author's
     content silently.
3. AGENTS.md rules block.
   - New file: copy `templates/AGENTS.template.md` to `AGENTS.md`.
   - Existing file: replace everything from the `BEGIN pvarki-agent-standard`
     line through the `END` line, inclusive, with the template's lines. Without
     markers, insert them after the title and purpose paragraph.
   - Add any template sections the file lacks. Move the confirmed old lines
     under the closest heading.
4. Fill in the repo sections from code and CI, not from old docs.
   - **Commands:** the exact setup, test and lint commands CI runs, with the
     coverage floor.
     - Read `.github/workflows/`, and follow `uses:` composite actions to their
       `run:` steps.
     - If prek is a dev dependency, use the repo's runner (e.g. `uv run prek`).
   - **Architecture & boundaries:** propose layers, directions and contracts
     from the template's core/edge/composition model, and mark each line
     `TODO(owner): confirm`. List current code that breaks the model under
     "Do not copy". The tripwire is a command that prints nothing while the
     boundaries hold (e.g. `git grep` for product names in core paths); if
     there isn't one yet, write `TODO(owner)`.
   - **Gotchas:** only what code, CI or confirmed old lines prove.
5. Per-agent files. Create them, or merge into existing files: keep the existing
   rules the template allows, and list the rest for the human:
   - `CLAUDE.md` from `templates/CLAUDE.template.md`. Claude-only lines go
     below `@AGENTS.md`.
   - `.claude/settings.json` from `templates/claude-settings.template.json`.
     - It carries the gates: prompt hooks on plan, commit, PR and finish. Keep
       them; add repo-specific gates only as prompt hooks.
     - Its deny rules stop agents from editing this file. On an update run in
       a repo that already has them, give the human the new file to apply.
     - Set `ref` to the harness release tag you copied from.
     - Keys the template doesn't have (`permissions.allow`, `env`, `model`,
       extra sandbox or plugin keys) aren't merged: the `pvarki-agent-files`
       hook rejects them. List them for the human as blocking; personal ones
       belong in that person's own `.claude/settings.local.json`.
     - Add the repo's package indexes (`[[tool.uv.index]]` in `pyproject.toml`,
       `.npmrc`, `pip.conf`) to `sandbox.network.allowedDomains`, and list them
       for the human.
   - `.gemini/settings.json` from `templates/gemini-settings.template.json`.
   - `.github/copilot/settings.json` from `templates/copilot-settings.template.json`.
   - `.gitignore`: add `.claude/worktrees/`, where Claude Code puts worktrees.
   - `CODEOWNERS`: whoever can change these files controls every contributor's
     agent. Ask the human for owners (`@user` or `@org/team` with write
     access) of `AGENTS.md`, `CLAUDE.md`, `.agents/`, `.claude/`, `.codex/`,
     `.cursor/`, `.gemini/`, `.github/`, `.mcp.json`, `.pre-commit-config.yaml`
     and the CODEOWNERS file itself. Put them in the file GitHub reads: the
     first of `.github/CODEOWNERS`, `CODEOWNERS`, `docs/CODEOWNERS`. Never
     commit a placeholder or empty owner; GitHub assigns no one. With no
     answer, list the proposed lines as blocking in the PR description.
6. Commit hooks. Compare the repo's autogenerated pre-commit section with
   pvarki/config-ci-library's current generated config for its language.
   Report any drift, but don't regenerate it here; that is a separate change.
   Below its `END AUTOGENERATED SECTION` line, add the harness's hooks, pinned
   to the commit of the release you copied from (`git -C <harness clone>
   rev-parse X.Y.Z^{commit}`, or without a clone `git ls-remote
   https://github.com/pvarki/markdown-pvarki-best_practises 'refs/tags/X.Y.Z^{}'`),
   never to a tag that can move.
   config-ci-library's CI runs them like any repo hook; it doesn't know about
   the harness:

   ```yaml
   -   repo: https://github.com/pvarki/markdown-pvarki-best_practises
       rev: <40-character commit sha>  # frozen: X.Y.Z
       hooks:
           -   id: pvarki-agent-files
           -   id: pvarki-no-attribution
           -   id: pvarki-no-local-settings
   ```

   On an update run, put
   `git -C <harness clone> diff <old>..<new> -- . ':(exclude)*.md'`
   in the PR description: that code runs in this repo's CI.

   Install the hooks with prek installed per user (`uv tool install prek`;
   if it's missing, ask the human), never from the repo's venv, so the git
   hook doesn't run a binary from inside the repo:
   `prek install --hook-type pre-commit --hook-type commit-msg`.
7. Check, after running the repo's setup command:
   - `git add` the new files, then run the lint command on them, e.g.
     `uv run prek run --files AGENTS.md CLAUDE.md .claude/settings.json .gemini/settings.json .github/copilot/settings.json`.
     Run `git diff`: formatters may have rewritten files. Add them and rerun
     until it is clean.
   - The rules block matches the template. This prints nothing:

     ```sh
     t="${TMPDIR:-/tmp}"
     sed -n '/BEGIN pvarki-agent-standard/,/END pvarki-agent-standard/p' AGENTS.md > "$t/block.repo"
     sed -n '/BEGIN pvarki-agent-standard/,/END pvarki-agent-standard/p' <skill-dir>/templates/AGENTS.template.md > "$t/block.tpl"
     diff "$t/block.repo" "$t/block.tpl"
     ```

   - Paths in AGENTS.md: `test -e` each one. Commands: run each one, or list
     the ones you didn't run.
   - AGENTS.md stays under 150 lines.
   - `<runner> prek run pvarki-agent-files --all-files` passes.
   - `grep '^PREK=' .git/hooks/pre-commit` names a prek outside the repo.
   - Default-branch protection, read only:
     `gh api repos/<owner>/<repo>/rules/branches/<default>` (rulesets) and
     `gh api repos/<owner>/<repo>/branches/<default> --jq .protection`
     (classic; shows required checks only). If merging doesn't require a PR
     with code-owner review, last-push approval and passing CI, with no
     bypass, note it as blocking in the PR description. List what you can't
     read as "needs an admin to confirm". Never change the settings yourself.
8. Commit locally, one context per commit (`docs: add agent rules`,
   `chore: add agent settings`). Don't push. In Claude Code (2.1.283 or newer),
   ask the human to run `/doctor prompt-audit`.

## Gotchas

- `agents.md` and `AGENTS.md` are the same file on macOS and Windows.
- A `CLAUDE.local.md` stops Claude Code from reading AGENTS.md natively; the
  `@AGENTS.md` import in CLAUDE.md still works.
- `attribution` in `.claude/settings.json` must stay an object. `false` makes
  older Claude Code skip the whole file, deny rules included.
- New settings apply from the next session. Until then a tool may still ask for
  attribution lines; the rules block wins.
- Cloud agents (Copilot, Codex cloud) open their own branches and PRs. Only
  the default-branch protection from step 7 keeps their work off the default
  branch.
